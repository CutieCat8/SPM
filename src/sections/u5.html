UNIT 5

Project Initiation & Planning

เขียนโครงการ วางแผน กำหนดขอบเขต และแตกงานเป็น WBS

5.1 Project Initiation — กิจกรรม 6 ข้อ

เป็นระยะที่เกิดหลังจากองค์กรคัดเลือกโครงการที่เหมาะสมที่สุดแล้ว ทีมงานต้องกำหนดขนาดและขอบเขตกิจกรรม ได้แก่

  1. การนิยามโครงการ และกำหนดเป้าหมาย
  2. การศึกษาความเป็นไปได้
  3. การกำหนดขอบเขตเบื้องต้นของโครงการ
  4. การประเมินมูลค่าโครงการ
  5. การกำหนดผู้มีส่วนได้ส่วนเสีย
  6. การพัฒนาเอกสารสิทธิ์ของโครงการ — ผลอนุมัติเป็นไปได้ 3 กรณี: ดำเนินการต่อ / ชะลอไว้ก่อน / ปฏิเสธ

2) Descriptive Style (แบบพรรณนาความ)

เขียนตามแบบฟอร์มที่หน่วยงานกำหนด นิยมใช้ทั่วไปโดยเฉพาะหน่วยงานราชการ องค์กรพัฒนาระหว่างประเทศ องค์กรพัฒนาเอกชน และองค์กรประชาชน

5.3 SOW vs Project Plan (ข้อนี้ออกสอบแน่)

Statement of Work (SOW)

เอกสารแสดงข้อตกลงร่วมกันระหว่างลูกค้าและบริษัท ประกอบด้วย 5 ส่วน:

  • ที่มาและความสำคัญ (Background/Problems)
  • วัตถุประสงค์ (Objectives)
  • คำอธิบายสินค้าหรือบริการ (Product Description)
  • ขอบเขตการดำเนินงาน (Scope)
  • สิ่งที่จะต้องส่งมอบ (Deliverables)
Project Plan

มี 5 ส่วนของ SOW บวกเพิ่มอีก 7 ส่วน:

  • กิจกรรมและความสัมพันธ์ (Tasks, Relationship & Dependence)
  • ระยะเวลาแต่ละกิจกรรม (Task Duration)
  • การวางแผนใช้ทรัพยากรตามหลัก 4M + 1E
  • ตารางกำหนดเวลา (Start & Completion Date)
  • การระบุความเสี่ยง (Risks)
  • การบริหารการเปลี่ยนแปลง (Change Management / Version Control)
  • เงื่อนไขการส่งมอบ (Delivery Instructions/Constraints)
4M + 1E คืออะไร

Material (วัสดุ) · Man (คน) · Machine (เครื่องจักร/เครื่องมือ) · Method (วิธีการ) · Environment (สภาพแวดล้อม)

5.4 Project Planning

การวางแผน = การกำหนดอนาคตล่วงหน้าเกี่ยวกับภารกิจหรือกิจกรรมต่างๆ ที่จะกระทำให้บรรลุวัตถุประสงค์
ผลผลิตของการวางแผน คือ ตัวแผน (Plan)

วัตถุประสงค์ของการวางแผน 4 ข้อ

  1. เพื่อกำหนดทิศทางของการดำเนินโครงการ
  2. เพื่อลดผลกระทบของการเปลี่ยนแปลง
  3. เพื่อลดความสูญเสียจากความผิดพลาดที่อาจเกิดขึ้น
  4. เพื่อเป็นมาตรฐานสำหรับการควบคุมการดำเนินโครงการ

Planning is to know: Project Characteristics · Product Characteristics · The Process and Activities · Their Sequences and Components

ขั้นตอนการวางแผนโครงการ 9 ขั้น

  1. รวบรวมข้อมูลและข้อเท็จจริง → รู้ปัญหาและความต้องการ
  2. วิเคราะห์ปัญหาและความต้องการ → รู้สาเหตุ
  3. กำหนดวัตถุประสงค์และเป้าหมาย → รู้ผลลัพธ์ของงานที่จะทำ
  4. การคิดค้นทางเลือก → รู้วิธีการต่างๆ
  5. วิเคราะห์และเปรียบเทียบทางเลือก → รู้ลำดับทางเลือก / เลือกทางที่เหมาะสม
  6. จัดทำข้อเสนอโครงการ (TOR/Project Proposal/Quotation)
  7. เสนอ Project Owner พิจารณา → ไม่อนุมัติให้กลับไปปรับปรุง
  8. จัดทำแผนโครงการ (Project Plan) โดย Project Team
  9. เสนอพิจารณาอีกครั้ง → อนุมัติจึงเริ่มดำเนินการ

กิจกรรมสำคัญในการวางแผน 2 อย่างแรก

01 Task Identification

การระบุงานที่ต้องทำ หากมีงานใดหายไปจะทำให้คำนวณเวลาส่งมอบผิดพลาด วิธีที่นิยมคือวาดแผนงานแบบโครงสร้างลำดับชั้น (Hierarchy) เริ่มจากงานหลักแล้วแตกเป็นงานย่อย — วิธีนี้เรียกว่า Work Breakdown Structure

02 Estimating Task Completion Time

ประมาณเวลาด้วย 3 ตัวแปร:
B = Best-case (เร็วที่สุด)
W = Worst-case (ช้าที่สุด)
P = Probable-case (เวลาจริงที่คิดว่าจะเสร็จ)

เวลาที่เหมาะสม = (B + 4P + W) ÷ 6 สังเกตว่าเป็นสูตรเดียวกับ PERT ใน Unit 6 เพียงเปลี่ยนชื่อตัวแปรเป็น O, M, P
ลองคำนวณ

→ (4 + 4×6 + 14) ÷ 6 = (4 + 24 + 14) ÷ 6 = 42 ÷ 6 = 7 วัน

5.5 Project Scope Management

ขอบเขตงาน (Scope) = กิจกรรมหรืองานทั้งหมดและขั้นตอนต่างๆ ที่เกี่ยวข้องกับการผลิตสินค้าหรือบริการของโครงการ
การกำหนดขอบเขต = กิจกรรมที่ใช้กำหนดและควบคุมส่วนประกอบที่ควรมีและไม่ควรมีในโครงการ เพื่อให้ทุกฝ่ายเข้าใจตรงกัน

Scope เป็นปัจจัยที่ต้องคำนึงถึงก่อนปัจจัยอื่นๆ เพราะแสดงภาพรวมและความสัมพันธ์ของปัจจัยทั้งหมด ถ้ากำหนดไม่ดีจะทำให้วางแผนผิดพลาด และส่งผลเสียร้ายแรงต่อต้นทุนและคุณภาพ

มิติของขอบเขตโครงการ 6 ด้าน

ขอบเขตด้านเวลาขอบเขตด้านพื้นที่ขอบเขตด้านเทคโนโลยี
ขอบเขตด้านประชากรขอบเขตด้านข้อมูลขอบเขตด้านจริยธรรม

คำถามที่ใช้กำกับแต่ละมิติ: "อะไรทำได้บ้าง?" และ "อะไรที่รวมอยู่ในโครงการ?" — ส่วนสิ่งที่ทำไม่ได้คือ ข้อจำกัด (Limitation)

5.6 Work Breakdown Structure (WBS)

WBS = การแบ่งหน้าที่หลักในแต่ละโครงการออกมาเป็นหน้าที่หรือกิจกรรมย่อย เพื่อให้บริหารจัดการและกระจายทรัพยากรได้ง่ายขึ้น
มีลักษณะเป็นแผนภูมิรากไม้ แบ่งเป็นระดับชั้น (Hierarchy) ตั้งแต่งานใหญ่ที่สุด จนถึงงานระดับย่อยที่สุดที่เป็น Work Package
Level 0 Project X Level 1 ├── งานหลัก A ── งานหลัก B ── งานหลัก C Level 2 │ ├── งานย่อย Level 3 │ │ └── Work Package ← ระดับล่างสุด
  • WBS ถือเป็นเอกสารเบื้องต้นในการบริหารจัดการโครงการ ที่แสดงหลักเกณฑ์ในการวางแผนและบริหารทรัพยากร
  • โครงสร้างที่ดีควรอธิบายถึง "ผลลัพธ์ที่อยากได้" ของแต่ละขั้นตอน
  • กิจกรรมใดที่ไม่จำเป็นต่อการดำเนินโครงการ ไม่ควรถูกแสดงไว้ใน WBS ← ข้อนี้ออกสอบบ่อย
  • แบ่งได้ 2 แนว: ตามกระบวนการบริหารโครงการ (Initiation / Planning / Execution / Control / Closure) หรือตามกลุ่มของงาน (Project Management, Systems Engineering, Software, Hardware, …)
  • ประโยชน์: กำหนดขอบเขตงานอย่างมีระบบ · ช่วยประเมินราคาและปริมาณทรัพยากร · จัดแบ่งหน้าที่ความรับผิดชอบ

วิธีการสร้าง WBS 5 วิธี (จำให้ครบ)

#วิธีสาระสำคัญ
1Using Guideline
วิธีการใช้คำแนะนำ		 สร้างตามแนวทางหรือคำแนะนำที่มีอยู่แล้ว องค์กรขนาดใหญ่จะกำหนดรูปแบบชัดเจน เพื่อให้ผู้ที่จะประมูลใช้เป็นแนวทาง — กรณีนี้หลีกเลี่ยงไม่ได้ ต้องทำตามที่เจ้าของโครงการแนะนำ
2Analogy Approach
วิธีการเปรียบเทียบ		 อาศัย WBS ของโครงการที่เคยทำมาแล้วและมีลักษณะคล้ายคลึงกัน มาเป็นจุดเริ่มต้น ข้อดีคือประหยัดทรัพยากร เช่น เวลา ค่าใช้จ่าย และบุคลากร
3Top-down Approach
วิธีจากบนลงล่าง		 เริ่มจากกิจกรรมกว้างๆ และใหญ่ที่สุดก่อน แล้วแตกเป็นกิจกรรมย่อย — เหมาะกับโครงการที่ผู้จัดการโครงการมีความรู้และประสบการณ์ด้านเทคนิคมากพอ และมองภาพรวมออกชัดเจน
4Bottom-up Approach
วิธีจากล่างขึ้นบน		 สมาชิกในทีมมีบทบาทมาก ช่วยกันกำหนดกิจกรรมให้เฉพาะเจาะจงและมากที่สุดเท่าที่เป็นไปได้ แล้วจัดรวมเป็นกลุ่มในระดับสูงขึ้น
ข้อเสีย: เสียเวลามาก
แต่: มีประสิทธิภาพมาก มักใช้กับโครงการ IT ที่สร้างสินค้า/บริการแนวใหม่ที่ยังไม่เคยมีใครทำ หรือโครงการที่ต้องการให้ทีมรู้สึกผูกพัน
5Mind-mapping Approach
วิธีวางแผนจากความคิด		 แตกความคิดหลักออกเป็นกิ่งก้านสาขา ทีมเริ่มสร้าง WBS ได้อย่างอิสระ โดยไม่ต้องมีโครงสร้างที่เป็นทางการ ส่งเสริมความคิดสร้างสรรค์ การมีส่วนร่วม และศีลธรรมอันดีในทีม

ข้อควรคำนึงในการสร้าง WBS 6 ข้อ

  1. ข้อมูลใน WBS ต้องสอดคล้องกับการดำเนินงานจริงของโครงการ
  2. กิจกรรมย่อยสุด (ระดับล่างสุด) ควรมีผู้รับผิดชอบเพียงคนเดียว แม้ผู้ร่วมทำกิจกรรมจะมีมากกว่า 1 คน
  3. สมาชิกทีมควรมีส่วนร่วมในการสร้าง WBS และทุกคนยอมรับและเห็นพ้องต้องกัน
  4. ทุกกิจกรรมควรกำหนดไว้เป็นลายลักษณ์อักษร เพื่อให้เข้าใจตรงกันเกี่ยวกับขอบเขตงาน
  5. WBS ต้องยืดหยุ่นได้ เพื่อรองรับการเปลี่ยนแปลง ขณะที่ยังควบคุมรายละเอียดได้เหมาะสม
  6. รายละเอียดของกิจกรรมหนึ่งๆ เป็นการสรุปรวบรายละเอียดของกิจกรรมที่อยู่ระดับล่างลงไป
