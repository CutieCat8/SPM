4.1 นิยาม

Project Identification (การค้นหาโครงการ)

กระบวนการอย่างเป็นระบบในการสร้างและระบุไอเดียของโครงการที่เป็นไปได้ เพื่อพัฒนาเป็นข้อเสนอเบื้องต้น

Output = List of Projects (รายการโครงการที่ต้องการดำเนินงาน พร้อมแหล่งที่มา/แผนก)

Project Selection (การเลือกสรรโครงการ)

การศึกษาไอเดียแต่ละโครงการอย่างละเอียด แล้วเลือกโครงการที่มีลำดับความสำคัญสูงสุด เพื่อพิจารณาและพัฒนาต่อ

ที่มาของโครงการอีกทางหนึ่ง: โครงการจากหน่วยงานอื่นที่ได้รับว่าจ้าง ผ่าน TOR — ด้วยการว่าจ้าง / การประมูล / การทาบทาม

4.2 Source of Project

Macro Project (ระดับมหภาค)

ความร่วมมือระดับชาติ ส่งผลกระทบเชิงพัฒนาเกินพื้นที่ท้องถิ่น ดำเนินการข้ามภูมิภาค — Macro-planning คือการวางแผนเชิงกลยุทธ์ภาพใหญ่ วิสัยทัศน์ระยะยาว
แหล่งไอเดีย: Entrepreneurs, Technical Experts, Progressive Farmers, Local Leaders, Mass Media, Bankers, National Policies

Micro Project (ระดับจุลภาค)

ความร่วมมือระดับองค์กร — Micro-planning อยู่ระดับโครงการรายตัว มีรายการงานและ timeline ละเอียด

ผู้เกี่ยวข้อง 4 กลุ่มกับลักษณะโครงการ (ตารางนี้ออกสอบบ่อย)

แหล่งที่มาต้นทุนระยะเวลาความซับซ้อนขนาดจุดมุ่งเน้น
Top Management
เช่น CEO		สูงที่สุดยาวนานที่สุดสูงที่สุดใหญ่ที่สุดกลยุทธ์
Steering Committee
ผู้บริหารระดับล่าง / ข้ามสายงาน		สูงยาวนานสูงใหญ่การทำงานร่วมกัน + วิเคราะห์ต้นทุน–กำไรเป็นแบบแผน
User Department
หัวหน้าหน่วยที่ร้องขอ		ต่ำสั้นต่ำเล็กภายในส่วนงาน ไม่มุ่งเน้นกลยุทธ์ พัฒนาเร็ว
Development Group
programmer, IS manager		ต่ำ–สูงสั้น–ยาวต่ำ–สูงเล็ก–ใหญ่บูรณาการกับระบบงานปัจจุบัน พัฒนาเร็ว มักไม่คำนึงต้นทุน/กำไร

4.3 แผนงาน vs โครงการ vs กลุ่มงาน vs งาน

แผนงาน (Program) ─── ชุดของโครงการตั้งแต่ 2 โครงการขึ้นไปที่สัมพันธ์กัน มีเป้าหมายเดียวกัน └─ โครงการ (Project) ─── กลุ่มของกิจกรรมที่สัมพันธ์กัน └─ กลุ่มงาน (Work Package) └─ งาน (Task)
Program = (Project 1, Project 2, …, Project n) → Goal
Project = (Activity 1, Activity 2, …, Activity n) → Target of Project

4.4 Project Feasibility Study — การศึกษาความเป็นไปได้

Feasibility Study = การศึกษาวิเคราะห์และจัดทำข้อมูลเพื่อแสดงเหตุผลสนับสนุนความเหมาะสมของโครงการ ว่านำไปสู่การปฏิบัติได้จริง และให้ผลประโยชน์ตอบแทนคุ้มค่าต่อการลงทุน

เกณฑ์จำแนกโครงการ (Project Classification) 6 เกณฑ์

  1. Value Chain Analysis — กิจกรรมในโครงการเพิ่มคุณค่าแก่สินค้า/บริการหรือไม่ โดยเฉพาะในมุมผู้บริโภค
  2. ความสอดคล้องกับกลยุทธ์ขององค์กร — ช่วยให้บรรลุเป้าหมายตามกลยุทธ์ข้อใดบ้าง
  3. ผลตอบแทนที่เป็นไปได้ — เพิ่มกำไรหรือเพิ่มลูกค้าได้ในช่วงเวลาหนึ่ง
  4. ความยากด้านเทคนิคและความเสี่ยง — บ่งบอกว่าเป็นโครงการเสี่ยงสูงหรือต่ำ
  5. ขนาดของโครงการ — พิจารณาขอบเขตงานและกลุ่มผู้มีส่วนได้เสีย
  6. ระยะเวลาดำเนินโครงการ — ระยะสั้น ≤ 1 ปี · ระยะกลาง 1–3 ปี · ระยะยาว 3 ปีขึ้นไป

ประโยชน์ของ Feasibility Study

เพิ่มโฟกัสให้ทีม · ค้นพบโอกาสใหม่ · จำกัดทางเลือกทางธุรกิจให้แคบลง · ระบุเหตุผลที่ไม่สมควรทำโครงการ · ให้ข้อมูลสำหรับการตัดสินใจ "go / no-go" · เพิ่มอัตราความสำเร็จโดยประเมินหลายพารามิเตอร์

ระดับความละเอียดตามประเภทโครงการ: โครงการเดิมที่เคยทำมาก่อน ไม่จำเป็นต้องศึกษาทุกด้าน / โครงการใหม่หรือโครงการนำร่อง (Pilot Project) ควรศึกษาทุกด้าน / โครงการภาครัฐเน้นสวัสดิการและความผาสุกของประชาชน / โครงการภาคเอกชนเน้นกำไรจากการลงทุนและการวิเคราะห์ตลาด

4.5 Project Selection — ผลการตัดสินใจ 5 แบบ

ผลการตัดสินใจความหมาย
1. ยอมรับโครงการ
Accept Project		เริ่มจัดทำโครงการและดำเนินการพัฒนาต่อไป
2. ปฏิเสธโครงการ
Reject Project		ไม่พิจารณาโครงการนั้นต่อ หรือระงับแล้วให้เสนอโครงการใหม่มาแทน
3. ชะลอโครงการ
Delay Project		องค์กรยังไม่พร้อม เมื่อพร้อมแล้วจะนำมาพิจารณาอีกครั้ง
4. ให้ผู้ใช้พัฒนาระบบเอง
End-user Development		ส่งผู้ใช้ไปฝึกอบรม แล้วให้พัฒนาระบบกันเองภายในองค์กร
5. ให้ทบทวนโครงการ
Proof of Project		ให้กลับไปเรียบเรียงหรือแก้ไขหลักการและเหตุผล แล้วนำมาเสนอใหม่

สิ่งที่ใช้ประกอบการตัดสินใจ: ความจำเป็น · รายชื่อโครงการ · ปัจจัยแวดล้อม · แหล่งทรัพยากรที่มีอยู่แล้ว · เกณฑ์การประเมิน

4.6 Scoring Model — วิธีให้คะแนนเปรียบเทียบโครงการ

เปรียบเทียบโครงการได้ 3 ฐาน: ตามวัตถุประสงค์องค์กร · ตามประโยชน์ที่จะได้รับ · ตามความเป็นไปได้แต่ละด้าน และแต่ละฐานให้คะแนนได้ 3 แบบ

วิธีวิธีคิด
เชิงปริมาณถามว่า "มี / ไม่มี" ใส่ X หรือ – แล้วนับจำนวน X
เชิงคุณภาพถามว่า "มีแล้วดีระดับไหน" ให้คะแนน เช่น 0–5 แล้วรวมคะแนน
เชิงคุณภาพแบบถ่วงน้ำหนักให้ น้ำหนัก (%) ของแต่ละเกณฑ์ แล้วคูณกับคะแนน → รวมเป็นคะแนนสุดท้าย น้ำหนักรวมต้องเท่ากับ 100%
ถ้าข้อสอบให้คำนวณ — ทำแบบนี้

สมมติเกณฑ์ "เพิ่มจำนวนลูกค้า" น้ำหนัก 30% โครงการ Social Commerce ได้ 5 คะแนน
→ คะแนนถ่วงน้ำหนัก = 5 × 0.3 = 1.5

ทำครบทุกเกณฑ์แล้วบวกรวม โครงการที่ได้คะแนนรวมสูงสุด = โครงการที่ควรเลือก
ข้อควรระวัง: ผลลัพธ์แบบไม่ถ่วงน้ำหนักกับแบบถ่วงน้ำหนักอาจให้คำตอบคนละโครงการ — ข้อสอบชอบถามตรงนี้
