แผนภาพช่วยเปลี่ยน Requirements ให้เป็นภาพร่วมระหว่างผู้ใช้ นักวิเคราะห์ และนักพัฒนา โดยบทนี้เน้น 3 แบบ: ER Diagram มองข้อมูล, Class Diagram มองโครงสร้างเชิงวัตถุ และ Sequence Diagram มองพฤติกรรมตามเวลา

Diagramคำถามหลักสิ่งที่เห็น
ER Diagramข้อมูลอะไรสัมพันธ์กับอะไรEntity, Attribute, Key, Relationship, Cardinality
Class Diagramระบบประกอบด้วยวัตถุแบบใดClass, Attribute, Method, Visibility, Class Relationship
Sequence Diagramใครเรียกใคร ตามลำดับเวลาอย่างไรObject, Lifeline, Message, Activation และ Fragment

UML.1 Entity Relationship Diagram (ERD)

ER Diagram คือแผนภาพโครงสร้างและความสัมพันธ์ของข้อมูลในฐานข้อมูล ใช้อธิบายองค์ประกอบและข้อกำหนดของฐานข้อมูล และเป็นสื่อกลางระหว่างผู้ใช้กับนักพัฒนา
  • Entity — กลุ่มสิ่งที่ต้องเก็บข้อมูล อาจเป็นบุคคล สถานที่ การกระทำ หรือกิจกรรม; สัญลักษณ์สี่เหลี่ยมผืนผ้า
  • Attribute — คุณลักษณะที่อธิบาย Entity/Relationship; สัญลักษณ์วงรี มีแบบธรรมดา, Primary Key, Multi-valued, Composite และ Derived
  • Relationship — ความสัมพันธ์ระหว่าง Entity; สัญลักษณ์สี่เหลี่ยมข้าวหลามตัด Entity หนึ่งมีหลายความสัมพันธ์หรือสัมพันธ์กับตัวเองแบบ Recursive ได้

Key ที่ต้องรู้: Primary Key ระบุระเบียนไม่ซ้ำ · Foreign Key อ้างอิง Primary Key ของอีกตาราง · Composite Key ใช้หลาย Attribute ร่วมกันเป็นกุญแจ

Cardinalityความหมายแนวแปลงเป็นตาราง
1 : 1A หนึ่งรายการสัมพันธ์กับ B ได้หนึ่งรายการวาง FK ในฝั่งที่เหมาะสม/บังคับมากกว่า และกำหนด Unique
1 : NA หนึ่งรายการสัมพันธ์กับ B ได้หลายรายการวาง FK ของฝั่ง 1 ไว้ในตารางฝั่ง N
M : Nทั้งสองฝั่งสัมพันธ์กันได้หลายรายการสร้าง Associative/Junction Table คั่นกลาง มี FK ไปทั้งสองฝั่ง
ตัวอย่าง Gym จากกิจกรรม

Member จอง ClassSession ซึ่งแต่ละ Session มี Trainer, Schedule และ Room: ความสัมพันธ์ Member ↔ ClassSession เป็น M:N จึงควรมี Booking เป็นตารางกลาง; Trainer 1:N ClassSession และ Room 1:N ClassSession

UML.2 Class Diagram

Class Diagram แสดงโครงสร้างระบบเชิงวัตถุในระดับสูง ทั้งคุณลักษณะ การดำเนินงาน ข้อจำกัด และความสัมพันธ์ Class เป็นแม่แบบ ส่วน Object เป็น instance ที่สร้างจากแม่แบบนั้น

┌──────────────────────────┐ │ ClassName │ ← ชื่อคลาส ├──────────────────────────┤ │ -attribute: DataType │ ← Attributes / Fields ├──────────────────────────┤ │ +method(param): Return │ ← Methods / Operations └──────────────────────────┘

Visibility: + Public เรียกจากภายนอกได้ · − Private เข้าถึงเฉพาะในคลาส · # Protected เข้าถึงได้ในคลาสและ subclass

ความสัมพันธ์ความหมายตัวอย่างจำ
Associationความเชื่อมโยงทั่วไปCustomer ทำ Order
InheritanceSubclass สืบทอดคุณสมบัติ/พฤติกรรมจาก SuperclassDog เป็น Animal
AggregationWhole–part แบบหลวม; Part อยู่ได้เองเมื่อแยกจาก WholePond มี Duck; เอา Duck ออก Pond ยังเป็น Pond
CompositionWhole–part แบบแน่น; Part ผูกกับวงจรชีวิตของ WholeElectric Car กับ Battery ตามตัวอย่างในสไลด์
Unidirectional AssociationA รู้จัก/เรียก B แต่ B ไม่จำเป็นต้องรู้จัก ABooking เข้าถึง Seat ฝ่ายเดียว
Aggregation vs Composition

ถามว่า “ถ้า Whole หาย Part ยังอยู่ได้ไหม?” — อยู่ได้ = Aggregation (เพชรโปร่ง) · อยู่ไม่ได้/วงจรชีวิตผูกกัน = Composition (เพชรทึบ)

ขั้นวาด Class Diagram 7 ขั้น

  1. Identify Classes
  2. List Attributes and Methods พร้อม Data Type/Visibility
  3. Identify Relationships
  4. Create Class Boxes
  5. Add Attributes and Methods
  6. Draw Relationships ด้วยเส้น/ลูกศรที่ถูกชนิดและทิศ
  7. Review and Refine ให้ตรงทั้งธุรกิจและเทคนิค

UML.3 Sequence Diagram

แสดงการส่ง Message ระหว่าง Object/Class ตามลำดับเวลา เพื่ออธิบายภาพรวมการทำงานและการสื่อสาร องค์ประกอบหลักคือ Objects, Lifelines, Messages และ Activation Bars โดยอ่านเวลาจากบนลงล่าง

Messageความหมาย
Synchronousผู้ส่งรอผู้รับประมวลผลและ Return ก่อนทำข้อความถัดไป; หัวลูกศรทึบ
Asynchronousผู้ส่งไม่รอผลตอบกลับ สามารถส่งข้อความถัดไปได้; หัวลูกศรเส้น
Returnส่งผลกลับหลังประมวลผล จะละเส้นก็ได้เพราะ Synchronous สื่อ Return โดยนัย
ReflexiveObject ส่ง Message หาตัวเอง ลูกศรเริ่มและจบบน Lifeline เดียวกัน
Creation / Destructionสร้าง Participant ระหว่างลำดับงาน / จบ Lifeline ด้วยเครื่องหมาย X

Sequence Fragment

alt = if / else

มีตั้งแต่ 2 ทางเลือก แบ่ง Interaction Operand ด้วยเส้นประ แต่ละส่วนมี Guard และทำเพียงทางเลือกที่เงื่อนไขจริง

opt = if

เหตุการณ์ทางเลือกเดียว เกิดเมื่อ Guard จริง; ไม่แบ่งหลาย Operand

loop = ทำซ้ำ

ทำจน Guard เป็น false; ระบุ minint และ maxint เพื่อจำกัดรอบต่ำสุด/สูงสุดได้

ref = อ้างแผนภาพอื่น

แยกส่วนของ Sequence ขนาดใหญ่ออกไปใช้ซ้ำ ระบุชื่อ Diagram ที่อ้างในกรอบ ref
